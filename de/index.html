Eine Webseite,
die dir erklärt, was eine Webseite ist.

Keine Vorkenntnisse nötig. Die Seite, die du gerade liest, ist selbst das Lehrbuch: Worüber du liest, das kannst du hier direkt auseinandernehmen. In der zweiten Hälfte öffnen wir die versteckten „Entwicklertools“ des Browsers (Taste F12), schauen uns das Skelett der Seite an, reden mit ihr und beobachten jedes Paket, das sie übers Internet verschickt und empfängt.

⏱ Etwa 40 Minuten 💻 Am besten am Computer mit Chrome / Edge / Firefox 🧪 In jedem Abschnitt etwas zum Ausprobieren

1Was ist eine Webseite eigentlich?

In einem Satz: Eine Webseite ist eine Textdatei, und der Browser macht daraus das, was du siehst.

Vielleicht denkst du, eine Webseite sei ein Bild oder etwas Geheimnisvolles. Sie ist viel schlichter: Eine Webseite ist im Kern ein geschriebener Text, der mit vereinbarten Zeichen sagt: „Das ist eine Überschrift“, „Hier kommt ein Bild hin“, „Dieser Button ist rot“.

📄 → 🖥️
Ein Vergleich: Noten und Pianist

Die Webseiten-Datei ist wie ein Notenblatt – nur Zeichen auf Papier. Der Browser ist der Pianist, der daraus Musik macht. Verschiedene Pianisten spielen dieselben Noten leicht unterschiedlich – deshalb sieht eine Seite in verschiedenen Browsern manchmal etwas anders aus.

🏪 ↔ 🧑
Woher kommen Webseiten?

Webseiten-Dateien liegen auf Computern irgendwo auf der Welt, die immer eingeschaltet sind. Diese heißen Server. Dein Browser ist der Client. Eine Seite öffnen = dein Browser fragt einen Server nach einer Datei, und der Server gibt sie ihm.

🧪 Ausprobieren: den „Originaltext“ dieser Seite ansehen
  1. Mache einen Rechtsklick auf eine leere Stelle dieser Seite und wähle „Seitenquelltext anzeigen“ (oder Strg+U, am Mac ⌘+⌥+U).
  2. Ein neuer Tab öffnet sich, voller Text und spitzer Klammern – das ist genau die Seite, die du gerade liest, in ihrer wahren Form.
  3. Drücke Strg+F und suche nach „Notenblatt“. Du findest den Absatz von oben.

Keine Sorge, wenn du nichts verstehst. Wichtig ist nur: Eine Webseite ist wirklich bloß Text.

💡 Webseite, Website, Browser, Internet – was ist der Unterschied? Eine Webseite ist eine einzelne Seite. Eine Website ist eine Sammlung zusammengehöriger Seiten (ein Shop hat Startseite, Produktseiten, Warenkorb). Ein Browser ist das Programm zum Anschauen (Chrome, Edge, Safari, Firefox). Das Internet ist das riesige Netz, das die Computer der Welt verbindet; Webseiten sind nur eins von vielen Dingen darin (Chatnachrichten und Onlinespiele laufen auch darüber).

2URLs lesen

Eine URL (Webadresse) ist die „Hausadresse“ einer Seite: Sie sagt dem Browser, wohin er gehen und welche Datei er holen soll.

Füge unten eine beliebige URL ein (z. B. aus deiner Adressleiste kopiert) – sie wird automatisch in Teile zerlegt:

TeilWas es istVergleich aus dem Alltag

🧪 Ausprobieren: Anker in Aktion

Schau dir das Inhaltsverzeichnis links an: Bei jedem Klick erscheint am Ende der Adressleiste etwas wie #console, und die Seite springt dorthin, ohne neu zu laden. Ändere jetzt das Ende der Adressleiste in #network und drücke Enter.

3Was passiert, nachdem du Enter drückst?

Vom Enter-Drücken bis zur fertigen Seite vergeht meist weniger als eine Sekunde. Wir spielen es 100-mal langsamer ab.

⌨️
① Du gibst die URL ein und drückst EnterDer Browser hat jetzt die „Hausadresse“.
📒
② Im Telefonbuch nachschlagen (DNS)Der Browser fragt einen DNS-Server: „Welche Nummer hat www.example.com?“ und bekommt eine IP-Adresse wie 93.184.215.14.
🤝
③ Verbindung aufbauenBrowser und Server „geben sich die Hand“. Bei https vereinbaren sie außerdem einen Geheimcode für die Verschlüsselung.
📨
④ Anfrage senden (Request)„Hallo, ich hätte gern /shop/schuhe.html. Ich bin Chrome und verstehe Deutsch.“
📦
⑤ Der Server antwortet (Response)„Status 200, bitte schön!“ und schickt die HTML-Datei zurück. Gibt es die Datei nicht, kommt der berühmte 404.
🔁
⑥ Der Browser liest das HTML und braucht noch mehr„Hier fehlen ein Bild, ein Stylesheet, ein Skript …“ – also schickt er viele weitere Anfragen. Eine Seite braucht oft Dutzende oder Hunderte!
🎨
⑦ Die Seite zeichnenDer Browser kombiniert Skelett (HTML) und Kleidung (CSS), malt alles auf den Bildschirm und führt dann die Bewegung (JavaScript) aus – jetzt kann man klicken und es bewegt sich.
📌 Merke dir diese zwei Wörter: Anfrage (Request) und Antwort (Response) Das ganze Web ist ein ständiges Frage-und-Antwort-Spiel. Gleich im Netzwerk-Panel der F12-Tools siehst du jede Frage und jede Antwort mit eigenen Augen.

4Die drei Geschwister: HTML, CSS, JavaScript

Fast jede Webseite besteht aus diesen drei Dingen. Am leichtesten merkt man sie sich mit einem Menschen als Vergleich.

🦴

HTML Skelett

Bestimmt, was auf der Seite ist: Überschriften, Absätze, Bilder, Buttons, Links. Inhalte werden in <Tags> verpackt.

👗

CSS Kleidung

Bestimmt, wie es aussieht: Farben, Schriften, Größen, Positionen, runde Ecken, Schatten, Animationen.

💃

JavaScript Bewegung

Bestimmt, was die Seite kann: was beim Klick passiert, Nachrichten live aktualisieren, Formulare prüfen, Spiele. Kurz „JS“.

Sieh selbst: Schicht für Schicht

Unten ist eine kleine Visitenkarte. Nimm den Haken bei CSS weg und sieh, wie eine Seite „ohne Kleidung“ aussieht; ohne JS reagiert der Button nicht mehr.

5Selbst eine Webseite bauen

Links den Code ändern, rechts sofort das Ergebnis sehen. Kaputt gemacht? Einfach „Zurücksetzen“.

Probier: Schreib deinen Namen ins <h1>; ändere color: tomato in color: green; klick den Button in der Vorschau.
🏠 Auf dem eigenen Computer? Öffne einen einfachen Texteditor (Editor unter Windows, TextEdit im Modus „reiner Text“ am Mac), füge den Code von links ein und speichere ihn als meine-seite.html (Endung .html, nicht .txt). Doppelklick auf die Datei – und dein Browser öffnet sie. Glückwunsch, das ist deine erste Webseite!

7Elemente (Elements): Skelett und Kleidung der Seite

Hier siehst du die HTML-Struktur der Seite in diesem Moment (den sogenannten DOM-Baum) und rechts die CSS-Kleidung jedes Elements.

Links: der DOM-Baum

Das ist HTML, aber live. Mit den ▶-Dreiecken auf- und zuklappen. Fährst du mit der Maus über eine Zeile, leuchtet der passende Teil der Seite auf.

Rechts: Stile (Styles)

Alles CSS des gewählten Elements. Werte ändern oder Regeln abhaken – das Ergebnis siehst du sofort. Weiter unten: „Berechnet“ (Computed) und das Box-Modell.

🧪 Aufgabe 1: Mit dem Auswahlwerkzeug klicken
  1. Öffne die DevTools und klick oben links auf das Symbol „Pfeil im Kasten“ ⬚↖ (oder Strg+Umschalt+C; Mac: ⌘+⇧+C).
  2. Fahr mit der Maus über die Seite: Farbige Markierungen erscheinen – das sind HTML-Elemente.
  3. Klick auf die Überschrift unten. Das Elemente-Panel springt direkt zu ihrem Code.

🧪 Aufgabe 2: Text und Farbe ändern
  1. Im Elemente-Panel den Text der Überschrift doppelklicken, irgendetwas eintippen, Enter. Die Seite ändert sich sofort!
  2. Rechts unter Stile element.style { } suchen, zwischen die geschweiften Klammern klicken, color: red tippen, Enter.

8Konsole (Console): direkt mit der Seite reden

Die Konsole hat zwei Aufgaben: ① Die Seite schreibt hier Protokolle und Fehler hinein; ② du kannst JavaScript eintippen, und die Seite führt es sofort aus.

👋 Die Seite redet die ganze Zeit mit dir Öffne die DevTools und klick auf den Tab Konsole / Console. Scroll etwas nach oben: Diese Seite hat dir beim Laden eine Nachricht hinterlassen (eine bunte Begrüßung).

① Nachrichten der Seite an dich

Klick die Buttons unten und schau dann in die Konsole. (Der schwarze Kasten unten ist ein „Spiegel“, damit du auch ohne F12 mitlesen kannst.)

Über die Filterleiste oben in der Konsole kannst du nur Fehler (Errors), Warnungen (Warnings) oder Infos anzeigen oder nach Stichwort filtern.

Deshalb verlangt Chrome beim ersten Einfügen, dass du allow pasting tippst – es schützt dich. Führe nur Code aus, den du verstehst.

9Netzwerk (Network): jedes Paket der Seite beobachten

Erinnerst du dich an „Anfrage“ und „Antwort“ aus Abschnitt 3? Das Netzwerk-Panel listet jede einzelne Anfrage als Zeile auf. Keine geht verloren.

🧪 Aufgabe 1: Alle Anfragen beim Laden einer Seite sehen
  1. DevTools öffnen und auf den Tab Netzwerk / Network klicken.
  2. Die Liste ist vielleicht leer – das Netzwerk-Panel zeichnet nur Anfragen auf, die nach dem Öffnen passieren.
  3. Drück F5 zum Neuladen. Die Liste füllt sich sofort: Die erste Zeile ist meist die HTML-Datei selbst, danach Stylesheet, Skript, Bilder usw.
🧪 Aufgabe 2: Eigene Anfragen erzeugen

Lass das Netzwerk-Panel offen, klick die Buttons unten und beobachte die neuen Zeilen:

NameStatusTyp (Type)Größe (Size)Zeit (Time)Wasserfall
(Eine Spiegeltabelle, die sich beim Klicken füllt; das echte Netzwerk-Panel zeigt viel mehr)

Was die Spalten bedeuten

SpalteBedeutung
NameDateiname oder Adresse der Anfrage.
StatusDer Statuscode des Servers (siehe unten). Rot heißt: fehlgeschlagen.
Typ (Type)document die Seite selbst, stylesheet CSS, script JS, img / svg Bilder, fetch/xhr Daten, die die Seite per JS anfordert, font Schriften.
Größe (Size)Wie viele Daten übertragen wurden. (disk cache) / (memory cache) heißt: Der Browser hat den Server gar nicht gefragt, sondern eine früher gespeicherte Kopie benutzt (den Cache).
Zeit (Time)Wie lange es vom Senden bis zur vollständigen Antwort gedauert hat. ms = Millisekunden; 1000 ms = 1 Sekunde.
Wasserfall (Waterfall)Eine Zeitleiste. Längere Balken sind langsamer; man sieht, welche Anfragen warten mussten und welche parallel liefen.

Statuscodes: die Antwort des Servers als Zahl

Beginnt mitBedeutet ungefährTypische Beispiele
2xxErfolg ✅200 OK alles gut
3xxGeh woanders hin / nimm, was du hast ↪301 dauerhaft umgezogen; 304 Not Modified unverändert, nimm deine Cache-Kopie
4xxProblem auf deiner (Client-)Seite 🙅404 nicht gefunden; 403 verboten; 401 bitte einloggen; 429 zu viele Anfragen
5xxProblem beim Server 🔥500 interner Serverfehler; 502/503 Server vorübergehend überlastet

Eine Zeile öffnen und ins Paket schauen

Klick im Netzwerk-Panel auf eine beliebige Zeile (z. B. das eben angefragte data.json), dann öffnen sich rechts Details:

Header (Headers)

Der „Versandschein“ auf dem Paket: URL, Methode (GET = holen, POST = abschicken), Statuscode, wie sich der Browser vorstellt (User-Agent), welcher Dateityp es laut Server ist (Content-Type) und mehr.

Vorschau (Preview)

Die Antwort hübsch aufbereitet: JSON-Daten als aufklappbarer Baum, Bilder werden angezeigt.

Antwort (Response)

Der rohe Inhalt, den der Server geschickt hat, Zeichen für Zeichen.

Zeitplan (Timing)

Wofür die Zeit dieser Anfrage draufging: Warteschlange, DNS-Abfrage, Verbindungsaufbau, Warten auf den Server, Herunterladen …

Ein paar sehr praktische Schalter

SchalterWofür

Cache deaktivieren (Disable cache)Immer frisch vom Server holen. Praktisch bei „Ich habe meine Seite geändert, warum sehe ich das nicht?“
Keine Drosselung (No throttling)Im Drop-down Slow 3G / 4G wählen, um eine langsame Handyverbindung zu simulieren. Neu laden und zusehen, wie die Seite Stück für Stück erscheint. Danach zurückstellen!
OfflineSo tun, als gäbe es kein Internet.
Filterleiste All / Fetch/XHR / JS / CSS / Img …Nur eine Art von Anfragen anzeigen.

🔒 Adresse beginnt mit file://? Wenn du diese Seite per Doppelklick auf die HTML-Datei geöffnet hast, kann der Button „Daten anfragen“ fehlschlagen (aus Sicherheitsgründen dürfen lokale Dateien nicht einfach andere Dateien lesen). Auch das ist eine Lektion: Lies, was der rote Text in Konsole und Netzwerk sagt. Online (z. B. über GitHub Pages) funktioniert es.

10Quellen (Sources): den Code „anhalten“

Das Quellen-Panel zeigt alle Dateien der Seite und kann JavaScript in einer Zeile anhalten, damit du Schritt für Schritt hindurchgehen kannst. Das nennt man „Debuggen mit Haltepunkten“.

Links die Dateiliste (die index.html dieser Seite, assets/app.js – dort steckt das ganze JavaScript –, assets/cat.svg usw.), in der Mitte der Code, rechts die Debug-Werkzeuge.

🧪 Aufgabe: Eine Berechnung mit debugger erwischen

Der Button unten berechnet die Summe eines Warenkorbs. Im Code steht ein debugger; – eine „Pausentaste“, die nur wirkt, solange die DevTools offen sind.

  1. Lass die DevTools offen (egal welcher Tab).
  2. Klick den Button unten. Die Seite „friert ein“, die DevTools springen zu Quellen und markieren die Zeile, in der angehalten wurde.
  3. Fahr mit der Maus über Wörter wie price und count, um ihre aktuellen Werte zu sehen. Rechts unter „Bereich“ (Scope) stehen sie auch.
  4. Mit F10 (Schritt) Zeile für Zeile weiter, oder mit F8 / ▶ fortsetzen.

Es geht auch ohne debugger: Im Quellen-Panel eine Datei öffnen und links auf eine Zeilennummer klicken. Eine blaue Markierung ist ein Haltepunkt; nochmal klicken entfernt ihn.

11Anwendung (Application): was die Seite auf deinem Computer speichert

Eine Seite kann Kleinigkeiten in deinem Browser ablegen, damit sie dich beim nächsten Mal wiedererkennt. In Firefox heißt dieses Panel „Web-Speicher“ (Storage).

🍪 Cookies

Kleine Zettel, die bei jeder Anfrage automatisch an den Server mitgeschickt werden. Meist, um sich „du bist eingeloggt“ zu merken.

📦 Local Storage

Ein lokales Schließfach, das auch nach dem Schließen des Browsers bleibt. Oft für Einstellungen wie den Dunkelmodus.

🗒 Session Storage

Ein Notizzettel, der verschwindet, sobald du den Tab schließt.

🧪 Aufgabe: Die Seite soll sich an dich erinnern
  1. Namen eingeben, „Speichern“ klicken, dann die Seite neu laden – sie kennt dich noch!
  2. DevTools → Anwendung / Application → links unter „Speicher“ (Storage) Local Storage aufklappen → die Adresse dieser Seite anklicken.
  3. Du siehst eine Zeile visitorName mit deinem Namen als Wert. Wert doppelklicken, ändern, neu laden.
  4. Unter Cookies gibt es außerdem einen Eintrag visited_lesson – ein kleiner Zettel, den diese Seite dir hinterlassen hat.
🧹 Was löscht „Cache und Cookies löschen“ eigentlich? Genau diese Dinge. Danach vergessen Websites dich (neu einloggen, Einstellungen zurück auf Standard). Im Anwendung-Panel gibt es links unter „Speicher“ (Storage) den Button Websitedaten löschen (Clear site data), der nur die aktuelle Website betrifft.

12Noch mehr Nützliches: Gerätemodus, Leistung, Check-up

📱 Gerätemodus: Der Computer spielt Handy

Neben dem Auswahlwerkzeug oben links in den DevTools ist ein Handy-+-Tablet-Symbol (Kürzel Strg+Umschalt+M; Mac: ⌘+⇧+M). Ein Klick, und die Seite schrumpft auf Handygröße. Oben kannst du ein Gerätemodell wählen und den Bildschirm drehen. Probier es jetzt: Auf dem Handy verschwindet das Inhaltsverzeichnis dieser Seite, und das Layout wird einspaltig. Solches Anpassen an den Bildschirm heißt Responsive Design.

⚡ Leistung (Performance): Warum ruckelt die Seite?

Klick den runden ⏺-Aufnahmeknopf, benutz die Seite ein paar Sekunden (z. B. hoch- und runterscrollen), dann Stopp. Du bekommst eine detaillierte Zeitleiste, womit der Browser jede Millisekunde beschäftigt war: Skripte ausführen (gelb), Stile und Layout berechnen (lila), Zeichnen (grün). Nicht schlimm, wenn du es nicht verstehst – wichtig ist nur: Ruckeln lässt sich aufzeichnen und analysieren.

Klick das während einer Leistungs-Aufnahme, dann siehst du einen großen gelben Block.

🩺 Lighthouse: Check-up mit einem Klick

Such oben in den DevTools Lighthouse (evtl. hinter » versteckt). Klick „Analyze page load“ (Seitenaufbau analysieren), und es bewertet die Seite von 0–100 in Leistung, Barrierefreiheit, Best Practices und SEO (Suchmaschinenfreundlichkeit) – samt Verbesserungstipps. Teste deine Lieblingsseiten!

🔎 Alles durchsuchen: das Befehlsmenü

In den DevTools Strg+Umschalt+P (Mac: ⌘+⇧+P) drücken und jede Funktion suchen. Tippe screenshot und wähle „Capture full size screenshot“, um die komplette lange Seite aufzunehmen; mit dark kannst du den Dunkelmodus simulieren.

14Spickzettel

BegriffIn einem Satz
BrowserDas Programm, das Webseiten herunterlädt und „zeichnet“.
ServerEin Computer, der Webseiten speichert und Anfragen beantwortet.
URL / WebadresseDie Adresse von etwas im Web.
DomainEin einprägsamer Servername wie example.com.
DNSDas Telefonbuch des Internets: übersetzt Domains in IP-Adressen.
HTTP / HTTPSDie Regeln, nach denen Browser und Server reden; HTTPS ist verschlüsselt.
Anfrage / AntwortDer Browser fragt nach etwas / der Server liefert es.
StatuscodeDie dreistellige Antwort des Servers, z. B. 200, 404, 500.
HTMLSkelett und Inhalt einer Seite.
CSSDas Aussehen einer Seite.
JavaScript (JS)Die Programmiersprache, die Seiten beweglich und interaktiv macht.
Tag / ElementEin HTML-Baustein wie <p> oder <img>.
DOMDer Elemente-Baum, den der Browser aus dem HTML im Speicher baut. Ändert JS ihn, ändert sich die Seite.
JSONEin verbreitetes Datenformat, das so aussieht: {"name": "Karotte"}.
CacheKopien von Dateien, die der Browser aufhebt, um sie nicht neu laden zu müssen.
Cookie / Local StorageKleine Daten, die eine Seite in deinem Browser ablegt.
Haltepunkt (Breakpoint)Eine Stelle, an der der Code pausiert, damit du ihn untersuchen kannst.
Responsive DesignSeiten, die sich an Computer, Tablet und Handy anpassen.
