One web page
that teaches you what a web page is.

No background needed. The page you're reading is the textbook: whatever you read about, you can take apart right here. In the second half we'll open the browser's hidden "developer tools" (press F12) and look at the page's skeleton, talk to it, and watch every parcel it sends and receives over the internet.

⏱ About 40 minutes 💻 Best on a computer with Chrome / Edge / Firefox 🧪 Hands-on tasks in every section

1What is a web page, really?

In one sentence: a web page is a text file, and the browser turns it into what you see.

You might think a web page is a picture, or something mysterious. It's much plainer than that: a web page is basically a piece of writing that uses agreed-upon symbols to say "this is a heading", "put a picture here", "this button is red".

📄 → 🖥️
An analogy: sheet music and a pianist

The web page file is the sheet music — just symbols on paper. The browser is the pianist who plays it as music. Different pianists play the same score slightly differently, which is why a page can look a little different in different browsers.

🏪 ↔ 🧑
Where do web pages come from?

Web page files live on computers somewhere in the world that are always switched on. Those are called servers. Your browser is the client. Opening a page = your browser asks a server for a file, and the server gives it.

🧪 Try it: see this page's "original text"
  1. Right-click an empty spot on this page and choose "View page source" (or press Ctrl+U; on a Mac ⌘+⌥+U).
  2. A new tab opens, full of text and angle brackets — that is the page you're reading, in its true form.
  3. Press Ctrl+F and search for "sheet music". You'll find the paragraph above.

Don't worry if it looks like gibberish. You only need to confirm one thing: a web page really is just text.

💡 Web page, website, browser, internet — what's the difference? A web page is one page. A website is a collection of related pages (a shop has a home page, product pages, a cart page). A browser is the program you use to view pages (Chrome, Edge, Safari, Firefox). The internet is the giant network connecting the world's computers; web pages are just one of many things travelling on it (chat messages and online games do too).

2Reading a URL

A URL (web address) is a page's "street address": it tells the browser where to go and which file to fetch.

Paste any URL into the box below (copy one from your address bar, for example) and it will be split into parts:

PartWhat it isReal-life analogy
Protocol https://Which "language" to use with the server. The s in https means secure (encrypted): nobody in between can read along.Sending a parcel by "sealed courier" vs. a postcard
Domain www.example.comThe server's name. Computers really find each other by numbers (IP addresses); domains are friendly names for humans."88 Main Street"
Path /shop/shoes.htmlWhich file or page on the server."3rd floor, room 302"
Query ?color=redExtra requests, starting with ? and joined with &."No onions, please" on a food order
Fragment #reviewsA spot on the page. Never sent to the server — it just tells the browser where to scroll.A bookmark in a book

3What happens after you press Enter?

From pressing Enter to seeing the page usually takes less than a second. Let's slow it down 100×.

⌨️
① You type the URL and press EnterThe browser now has the "street address".
📒
② Look it up in the phone book (DNS)The browser asks a DNS server: "What's the number for www.example.com?" and gets an IP address like 93.184.215.14.
🤝
③ ConnectBrowser and server "shake hands". With https they also agree on a secret code for encryption.
📨
④ Send a request"Hi, I'd like /shop/shoes.html please. I'm Chrome, and I read English."
📦
⑤ The server responds"Status 200, here you go!" and sends the HTML file back. If the file doesn't exist, you get the famous 404.
🔁
⑥ The browser reads the HTML and needs more"This needs a picture, a stylesheet, a script…" so it sends lots more requests. A single page often makes dozens or even hundreds!
🎨
⑦ Draw the pageThe browser combines the skeleton (HTML) with the clothes (CSS), paints it on screen, then runs the movement (JavaScript) so the page can be clicked and animated.
📌 Remember these two words: Request and Response The whole web is one long conversation of questions and answers. Soon, in the F12 Network panel, you'll see every question and every answer with your own eyes.

4The three siblings: HTML, CSS, JavaScript

Almost every web page is made of these three things. A person is the easiest way to remember them.

🦴

HTML skeleton

Decides what is on the page: headings, paragraphs, images, buttons, links. It wraps content in <tags>.

👗

CSS clothes

Decides how it looks: colours, fonts, sizes, positions, rounded corners, shadows, animations.

💃

JavaScript movement

Decides what it can do: what happens on click, live-updating messages, form checks, games. Often just "JS".

See it for yourself: layer by layer

Below is a little profile card. Untick CSS to see a page "without clothes"; untick JS and the button stops listening to you.

Ginger the Cat

Job: napping · Hobby: eating

See the three pieces of code behind this card 
<!-- HTML: what's there -->
<div class="profile">
  <img src="cat.svg">
  <h4>Ginger the Cat</h4>
  <button>❤ Like</button>
</div>
/* CSS: how it looks */
.profile img { border-radius: 50%; }      /* round avatar */
.profile button { background: #ff5a5f; } /* red button */
// JavaScript: what it does
let count = 0;
button.onclick = () => {
  count = count + 1;             // add one per click
  countText.textContent = count; // write the new number on the page
};

HTML tags: the page's building blocks

In HTML, each piece of content is wrapped in a pair of tags: <start>content</end>. The most common ones:

TagMeaningExample
<h1>–<h6>Headings; h1 is the biggest<h1>My Blog</h1>
<p>Paragraph<p>Nice weather today.</p>
<a>Link; href says where it goes<a href="https://...">Click</a>
<img>Image; needs no closing tag<img src="cat.png">
<button>Button<button>Submit</button>
<div>A "box" for grouping things<div>...</div>

Things inside a tag like src, href and class are called attributes — extra details about that block.

Tips: ↑ brings back the previous command; Tab autocompletes; Shift+Enter adds a new line without running; the 🚫 icon at the top (or Ctrl+L) clears the screen.

🚨 Safety warning: never paste code from strangers into the Console Scammers say things like "paste this into the F12 Console to get free coins / see who blocked you / unlock premium". In reality that code runs as you on that site and can steal your login, send messages or move money in your name. This is called "Self-XSS". That's why Chrome makes you type allow pasting the first time you paste — it's protecting you. Only run code you understand.

9Network: peek at every parcel the page sends and receives

Remember "request" and "response" from section 3? The Network panel lists every single request as a row. None are missed.

🧪 Task 1: see every request while a page loads
  1. Open DevTools and click the Network tab.
  2. The list may be empty — Network only records requests made after it was opened.
  3. Press F5 to reload. The list fills up instantly: the first row is usually the HTML file itself, followed by the stylesheet, script, images and so on.
🧪 Task 2: make your own requests

Keep the Network panel open, click the buttons below, and watch the new rows appear:

What each column means

ColumnMeaning
NameThe file name or address requested.
StatusThe server's status code (see below). Red means it failed.
Typedocument the page itself, stylesheet CSS, script JS, img / svg images, fetch/xhr data the page asked for with JS, font fonts.
SizeHow much data was transferred. (disk cache) / (memory cache) means the browser didn't ask the server at all and used a copy it saved earlier (the cache).
TimeHow long from sending the request to receiving the full response. ms = milliseconds; 1000 ms = 1 second.
WaterfallA timeline. Longer bars are slower; you can see which requests waited in line and which ran in parallel.

Status codes: the server's reply in code

Starts withRoughly meansCommon examples
2xxSuccess ✅200 OK all good
3xxGo elsewhere / use what you have ↪301 moved permanently; 304 Not Modified unchanged, use your cached copy
4xxProblem on your (the client's) side 🙅404 not found; 403 forbidden; 401 please log in; 429 too many requests
5xxProblem on the server 🔥500 internal server error; 502/503 server temporarily overwhelmed

Open a row and look inside the parcel

In Network, click any row (for example the data.json you just requested) and details open on the right:

Headers

The "shipping label" on the parcel: URL, method (GET = fetch, POST = submit), status code, the browser introducing itself (User-Agent), what type of file the server says it is (Content-Type), and more.

Preview

The response shown nicely: JSON data becomes a collapsible tree, images are displayed.

Response

The raw content the server sent back, exactly as received.

Timing

Where this request's time went: queueing, DNS lookup, connecting, waiting for the server, downloading…

🧪 Task: catch a calculation with debugger

The button below calculates the total for a shopping cart. The code contains a debugger; statement — a "pause button" that only works while DevTools is open.

  1. Keep DevTools open (any tab).
  2. Click the button below. The page "freezes", DevTools jumps to Sources and highlights the line where it stopped.

11Application: what the page stores on your computer

A page can keep small things in your browser so it remembers you next time. In Firefox this panel is called "Storage".

🍪 Cookies

Little notes that are sent to the server automatically with every request. Mostly used to remember "you're logged in".

📦 Local Storage

A local locker that survives closing the browser. Often used for settings like dark mode.

🗒 Session Storage

A sticky note that disappears when you close the tab.

🧪 Task: make the page remember you
  1. Type your name, click "Save", then reload the page. It still knows you!
  2. Open DevTools → Application → under "Storage" on the left, open Local Storage → click this site's address.
  3. You'll see a row visitorName whose value is your name. Double-click the value, change it, and reload.
  4. Under Cookies there's also a visited_lesson entry — a little note this page left you.
🧹 What does "clear cache and cookies" actually clear? Exactly this stuff. Afterwards sites forget you (you'll need to log in again, settings go back to default). In Application, the "Storage" page on the left has a Clear site data button that clears only the current site.

12More handy tools: device mode, performance, audits

📱 Device mode: pretend your computer is a phone

Next to the picker in the top-left of DevTools is a phone + tablet icon (shortcut Ctrl+Shift+M; Mac: ⌘+⇧+M). Click it and the page shrinks to phone size. At the top you can pick a device model and rotate the screen. Try it now: on a phone, this page's table of contents disappears and the layout becomes one column. Design that adapts to the screen like this is called responsive design.

⚡ Performance: why is the page laggy?

Click the round ⏺ record button, use the page for a few seconds (scroll up and down, say), then click stop. You get a detailed timeline of what the browser was busy with every millisecond: running scripts (yellow), calculating styles and layout (purple), painting (green). It's fine if you don't understand it — just know that lag can be recorded and analysed.

Click this while recording in Performance and you'll see a big yellow block.

🩺 Lighthouse: a one-click check-up

Find Lighthouse at the top of DevTools (it may be hidden under »). Click "Analyze page load" and it scores the page from 0–100 on performance, accessibility, best practices and SEO (how search-engine friendly it is), and tells you how to improve. Try it on your favourite websites!

🔎 Search everything: the Command Menu

Inside DevTools press Ctrl+Shift+P (Mac: ⌘+⇧+P) to search any feature. Type screenshot and choose "Capture full size screenshot" to capture the whole long page; type dark to emulate dark mode.

14Cheat sheet

TermIn one sentence
BrowserThe program that downloads web pages and "draws" them.
ServerA computer that stores web pages and answers requests.
URLThe address of something on the web.
DomainA memorable server name, like example.com.
DNSThe internet's phone book: turns domain names into IP addresses.
HTTP / HTTPSThe rules browsers and servers use to talk; HTTPS is the encrypted version.
Request / ResponseThe browser asks for something / the server sends it.
Status codeThe server's three-digit reply, like 200, 404, 500.
HTMLA page's skeleton and content.
CSSA page's look.
JavaScript (JS)The programming language that makes pages move and react.
Tag / elementAn HTML building block, like <p> or <img>.
DOMThe tree of elements the browser builds in memory from the HTML. Change it with JS and the page changes.
JSONA common data format that looks like {"name": "Ginger"}.
CacheCopies of files the browser kept so it doesn't have to download them again.
Cookie / Local StorageSmall bits of data a page keeps in your browser.
BreakpointA spot where code pauses so you can inspect it.
Responsive designPages that adapt to computers, tablets and phones.
